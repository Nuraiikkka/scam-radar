# Исследовательское обучение Scam Radar

Первый эксперимент выполнен 16 октября 2026 года на CPU. Это бинарная модель
по речи и OCR, а не модель пяти категорий и не обучение по пикселям видео.
Модель подключена к API: после извлечения речи и OCR сервер вызывает тот же
сервис, что и CLI. Категории определяют правила, бинарный прогноз виден в
`ml_prediction`, общий вывод — в `verdict`. Запуск описан в [основном README](../README.md).

## Данные и ограничения

Источник: Jules Gregory Agustin,
[Multimodal Filipino Scam Video Dataset / OptiScam, версия 6](https://www.kaggle.com/datasets/julesgregoryagustin/training-filipino-scam-dataset).
Лицензия исходного Kaggle-набора: **CC BY-NC-SA 4.0**. Сохраняйте атрибуцию,
некоммерческие условия и share-alike при дальнейшей работе. У связанной модели
на Hugging Face указана другая лицензия; она не заменяет лицензию исходных данных.

Скачиваются только JSON с текстом и разметкой. Кадры, WAV и большой архив не
скачивались. Исходные материалы хранятся в `data/raw/optiscam`, нормализованные
записи — в `data/processed/optiscam.jsonl`. Эти каталоги исключены из Git.

Разметка неоднородна: rank 0 означает автоматическую проверку агентом, а не
подтверждённую человеком истинность. Rank 1 — метка из companion JSON. Rank 2
в этом эксперименте не используется. Мы независимо не переразмечали ролики.
Тексты вердиктов, объяснения, названия категорий и пути файлов в признаки не
попадают. Заголовки/описания также исключены, чтобы приблизиться к текущему API.

Полный аудит и результаты: `reports/dataset_audit.md`,
`reports/collection.json`, `reports/baseline_metrics.json`.

## Повторение

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements/ml.txt
.\.venv\Scripts\python.exe ml/collect_optiscam.py
.\.venv\Scripts\python.exe ml/train_baseline.py
.\.venv\Scripts\python.exe -m pytest ml/tests -q
```

Сбор требует доступа в интернет. Используется воспроизводимая случайная
выборка до 50 записей на класс/тему с seed 42. Недоступные записи учитываются
в отчёте. Повторный сбор использует кеш и не гарантирует точного воспроизведения
при изменении доступности источника; поэтому отчёт содержит хеш входного JSONL.
При смене версии датасета сбор останавливается для повторной проверки.

Модель: word/character TF-IDF + LogisticRegression. Словарь и веса обучаются
только на train. Параметр C и порог выбираются только на validation. Test
используется после выбора конфигурации. Сохраняются состав разбиения и прогнозы.
Одинаковые ID, известные авторы и точные/близкие тексты объединяются в группы.
В исходных JSON нет author_id: независимость по авторам **не обеспечена**;
близость по картинке тоже не проверяется. Это ограничение текущего результата.

Модель сохранена локально в `artifacts/models/binary_baseline.joblib`.
Загружайте только собственные доверенные joblib-файлы.

## Проверка своего текста

Сохраните распознанную речь в UTF-8-файл `transcript.txt`, при необходимости OCR
в `ocr.txt`, и выполните:

```powershell
.\.venv\Scripts\python.exe ml/predict_baseline.py --text-file transcript.txt --ocr-file ocr.txt
```

`--ocr-file` необязателен. Выход — экспериментальная бинарная оценка, а не
подтверждение мошенничества и не категория проекта.

## Ограничения подключённой экспериментальной модели

Нужны независимо проверенные ролики всех пяти категорий, сложные безопасные
контрпримеры, разметка авторов/кампаний, проверка дубликатов видео и отдельный
свежий TikTok-тест. Для русского/казахского языка нужны отдельные примеры.
В проверку должны входить отказы Whisper/OCR и ролики без звука. Порог нужно
выбирать с учётом допустимого количества ложных обвинений. Текущие результаты
не подтверждают качество на всех этих условиях.
